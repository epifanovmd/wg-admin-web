# WG Admin: инструкция

Эта инструкция объясняет простым языком, что есть в админке, зачем это нужно
и как настроить VPN под разные задачи. Технические подробности устройства —
в документации бэкенда (`docs/WIREGUARD.md` в репозитории бэкенда).

## Коротко: что это

WG Admin управляет VPN на WireGuard на ваших серверах. Вы добавляете сервер,
ставите на него агента, создаёте VPN-сервер (интерфейс) и выдаёте людям
подключения (пиров). Всё остальное — пересылка трафика между серверами,
резервирование, прокси — настраивается в той же админке, без ручной работы на
серверах.

## Словарь

| Слово                 | Что это простыми словами                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------- |
| **Нода**              | Ваш сервер (VPS). На нём работает агент — маленькая программа, которая выполняет настройки из админки |
| **Агент**             | Программа на сервере. Сама забирает настройки у админки и применяет их. Входящие порты ей не нужны    |
| **Интерфейс**         | VPN-сервер на ноде: своя подсеть адресов и свой порт. К нему подключаются клиенты                     |
| **Пир**               | Одно подключение: телефон, ноутбук, роутер. У пира свой конфиг и QR-код                               |
| **Точка подключения** | Адрес, который видят клиенты. Позволяет менять серверы, не меняя конфиги у людей                      |
| **Релей**             | Нода, которая принимает трафик клиентов и пересылает его на другую ноду                               |
| **IPIP-туннель**      | Внутренний канал между двумя нодами. Помогает, когда прямой UDP до сервера теряется                   |
| **Реплика (копия)**   | Копия интерфейса на другой ноде с теми же пирами. Резерв на случай, если основной сервер упал         |
| **Проброс**           | Порт на релее, который ведёт на какой-то ваш сервис (не на интерфейс админки)                         |
| **Прокси**            | SOCKS5-прокси (например, для Telegram), защищённый сертификатом устройства и паролем                  |
| **Handshake**         | Последнее «рукопожатие» клиента с сервером. Свежее 3 минут — клиент на связи                          |

## Разделы меню

| Раздел            | Для чего                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| Дашборд           | Общая картина: скорость, трафик, ноды онлайн                                |
| Пиры              | Все подключения (или только ваши, если вы обычный пользователь) с фильтрами |
| Ноды              | Серверы: статус агента, связность между нодами, интерфейсы, метрики, журнал |
| Точки подключения | Адреса для клиентов                                                         |
| Пробросы          | Что пересылают релеи: ручные пробросы и точки подключения через релей       |
| Прокси            | SOCKS5-прокси: пользователи, устройства, скачивание клиента                 |
| Статистика        | Графики трафика и скорости за период                                        |
| Задачи            | Установка и удаление агентов: прогресс и журнал                             |

Всё обновляется само, в реальном времени — перезагружать страницу не нужно.
Пока админка открыта, агенты присылают статистику каждую секунду; графики
скорости на страницах ноды, интерфейса и пира сразу показывают последние
10 минут.

Внизу меню профиля (на телефоне — внизу мобильного меню) видны версии: **Веб**,
**API** и **Агент** — версия агента, которую админка ставит на ноды. Если агент
на какой-то ноде отличается от неё, в списке нод в колонке «Агент» у этой ноды
появится значок **обновление**.

Многие переключатели в формах показывают под собой пояснение к выбранному
варианту — прочитайте его, прежде чем сохранять.

Кнопки создания («Новая нода», «Новая точка», «Новый проброс», «Новый прокси»,
«Новый пир» в разделе «Пиры») — справа в шапке раздела. На странице ноды
«Новый интерфейс», на странице интерфейса «Новый пир» — справа в строке вкладок.
Кнопки создания и изменения видны только тем, у кого есть право управления.

## Первый запуск: от сервера до подключения

### Шаг 1. Добавить ноду

**Ноды → Новая нода** (в шапке раздела). Укажите название и публичный адрес сервера (IP или
домен) — он попадёт в конфиги клиентов, если не задана точка подключения.
После создания админка покажет ключ агента и готовую команду установки.

### Шаг 2. Установить агента

Два способа, результат одинаковый:

- **Из админки по SSH** — на странице ноды «Установить агента»: хост, пользователь,
  SSH-ключ или пароль. Прогресс виден прямо на странице и в разделе «Задачи».
- **Вручную** — выполнить на сервере команду из окна «Ключ агента»:
  `curl -fsSL <адрес админки>/api/v1/wg-agent/install.sh | sudo sh -s -- --key <ключ>`

Нужен Linux с systemd. Когда агент выйдет на связь, статус ноды станет
**Online**.

### Шаг 3. Создать интерфейс

На странице ноды, вкладка **Интерфейсы → Новый интерфейс**:

- **Имя** — например `wg0`.
- **Порт** — UDP-порт сервера, например `51820`. На одной ноде у каждого
  интерфейса свой порт.
- **Подсеть IPv4** — адреса для клиентов, например `10.8.0.1/24` (сервер
  получит `.1`, клиенты — следующие свободные).
- **DNS клиентов** — например `1.1.1.1`.
- **NAT** — включите, если клиенты должны выходить в интернет через этот
  сервер (обычный VPN).
- **Точка подключения** — пока можно не указывать (см. сценарии ниже).

Агент поднимет интерфейс за несколько секунд, статус станет **Up**.

### Шаг 4. Добавить пира и раздать конфиг

На странице интерфейса, вкладка **Пиры → Новый пир**. Ключи и адрес
выдаются автоматически. Затем кнопка **QR и конфиг**: отсканируйте QR в
приложении WireGuard на телефоне или скачайте `.conf` для компьютера.

Готово: клиент подключается, в таблице пиров видны трафик и handshake.

## Сценарии

### 1. Обычный VPN на одном сервере

Нода → агент → интерфейс с NAT → пиры. Точка подключения не нужна.

### 2. Несколько стран

Добавьте по ноде на каждый сервер и по интерфейсу на каждой. Одному человеку
можно выдать пиров на разных интерфейсах — выбирать страну он будет
переключением профиля в приложении WireGuard.

### 3. Сервер недоступен напрямую или UDP теряется

Бывает, что хостер или провайдер режет UDP до сервера, или сервер из-за
границы работает плохо. Тогда клиенты подключаются к «хорошей» ноде (релею),
а та пересылает трафик на нужный сервер по внутреннему туннелю.

1. **Точки подключения → Новая точка**: режим **Через релей панели**,
   релей-нода — хорошо доступный сервер, **пересылка до ноды интерфейса** —
   **Через IPIP-туннель**, **маршрут** — «Авто» (так и предлагается по
   умолчанию).
   «Хост для клиентов» — адрес релея. Релеем не может быть нода, на которой
   работает интерфейс этой точки или его копия.
2. В настройках интерфейса выберите эту точку и **порт на точке** — порт на
   релее, к которому будут подключаться клиенты (у каждого интерфейса через
   этот релей свой).
3. Раздайте конфиги заново (адрес в них изменится).

Туннель, адреса и правила система настроит сама. Здоровье туннеля видно на
странице ноды («Туннели»).

**DNAT или IPIP?** «Напрямую (DNAT)» просто переадресует пакеты на публичный
адрес сервера — выберите его, если прямой UDP до сервера работает, а нужен только
единый адрес. IPIP — если прямой путь теряет пакеты.

**Маршрут** (только для IPIP): «Авто» — через туннель, а если он не отвечает
~30 секунд — напрямую на ту же ноду; «Только туннель» — без прямого пути;
«Напрямую» — мимо туннеля, например пока его чинят.

Куда ведёт точка, видно в колонке «Куда ведёт» списка точек и в окне
редактирования точки («Интерфейсы через точку»): порт → интерфейс на ноде и
число копий. Если настройки точки, скорее всего, поведут трафик не туда (хост —
адрес другой ноды, релей — нода одного из интерфейсов точки и т. п.), форма
предупредит об этом.

### 4. Хочу менять серверы, не трогая конфиги людей

Сразу создавайте интерфейсы с точкой подключения. Точка — постоянный адрес
для клиентов: сервер за ней можно заменить, а интерфейс — **перенести** на
другую ноду (кнопка «Перенести» в таблице интерфейсов). Ключ и пиры
сохраняются, конфиги у людей остаются прежними.

Для точки в режиме «Адрес ноды» достаточно стабильного домена, который вы
переводите на новый IP сервера. Хост такой точки должен вести прямо на ноду
интерфейса: админка трафик через неё не пересылает.

### 5. Резерв на случай падения сервера

Нужна точка подключения **через релей панели** (у клиентов должен быть один
постоянный адрес). С точкой «Адрес ноды» или без точки копия — только резерв
для ручного переноса: трафик на неё сам не переключится (окно копирования об
этом предупредит).

1. В таблице интерфейсов ноды нажмите **Скопировать на ноду** и выберите
   резервный сервер. Появится копия с теми же пирами. Если на резервной ноде
   ещё нет агента, копия будет «Ожидает агента» и поднимется после установки.
2. Релей сам следит за копиями: если основной сервер перестал отвечать
   (~30 секунд), трафик уходит на копию, а когда основной ожил — возвращается.
3. Копии видны на странице интерфейса в блоке «Копии на нодах»: нода, основная
   или копия, статус; там же пишется, куда сейчас идёт трафик, и убирается
   ненужная копия. На странице ноды во вкладке «Интерфейсы» есть и копии чужих
   интерфейсов, работающие на этой ноде (с отметкой «трафик здесь», если релей
   шлёт трафик на неё); копию оттуда можно только убрать с этой ноды.
4. Закрепить трафик на конкретной копии — например, перед плановыми работами
   на основном сервере — можно в разделе **Пробросы**, блок «Точки подключения
   через релей» (кнопка «Управление трафиком» в блоке копий ведёт туда):
   «Авто» или «Только <нода>». Копию, где интерфейс не поднят, выбрать нельзя.

### 6. Пробросить порт на свой сервис

Например, у вас на сервере уже работает свой WireGuard или прокси, и клиенты
должны подключаться к нему через другой сервер.

**Пробросы → Новый проброс:**

- **Релей** — нода, на которую приходят клиенты;
- **Протокол** и **порт на релее**;
- **Нода-цель** (если там стоит агент) или **прямой адрес цели**, и **порт
  цели**;
- **Путь**: «Напрямую (DNAT)» или «Через IPIP-туннель» (нужна нода-цель с
  агентом). Для туннеля **маршрут** «Авто» сам переключится на прямой путь,
  если туннель лёг, и вернётся обратно.

Если порт цели — интерфейс админки на ноде-цели, форма предупредит: проброс
ведёт только на эту ноду и на копии не переключится. Для VPN-интерфейсов
используйте точку подключения через релей панели — такие точки видны на той же
странице, в блоке «Точки подключения через релей».

Хотите перейти со старого прокси без простоя? Создайте проброс **выключенным**
заранее, затем выключите старый прокси и включите проброс — агент займёт порт,
как только тот освободится.

Выключенный проброс порт на релее не держит. Чтобы перевести интерфейс с
ручного проброса на точку через релей на том же порту: выключите проброс, затем
выберите точку в настройках интерфейса. Проброс можно оставить для отката, но
включить его снова получится, только когда порт на релее свободен.

### 7. Прокси для Telegram

**Прокси → Новый прокси:** нода, порт на ноде. Если прокси доступен клиентам
через проброс на другом сервере — укажите адрес и порт для клиентов.

1. **Пользователь** — укажите логин, пароль сгенерируется автоматически и
   сразу покажется вместе со ссылкой для Telegram (позже — кнопка с ключом у
   пользователя).
2. **Устройство** — выпускается сертификат для конкретного компьютера или
   телефона.
3. У устройства — **Клиент для Mac**: готовый архив для macOS с сертификатом
   устройства и логином первого включённого пользователя. `install.sh` из архива
   сам ставит stunnel, настраивает автозапуск и поднимает локальный прокси
   `127.0.0.1:1080`. В Telegram: SOCKS5, `127.0.0.1:1080`, логин и пароль
   пользователя.

Потеряли устройство — **отзовите** его сертификат: соединения этого устройства
оборвутся сразу, остальные продолжат работать.

### 8. Пользователи сами управляют своими подключениями

Обычный пользователь (роль `user`) видит в разделе «Пиры» только свои
подключения: может скачать конфиг и QR, включить или выключить пира. Чтобы
пир появился у человека, укажите его **держателем** при создании пира.

### 9. Временный доступ

При создании пира задайте **«Действует до»**. После этой даты пир выключится
сам.

### 10. Своё устройство с собственным ключом

Если человек сгенерировал ключи сам (например, на роутере), при создании пира
вставьте его **публичный ключ** в поле «Импорт: публичный ключ клиента».
Приватный ключ тогда нигде не хранится, и конфиг с QR админка не выпускает —
человек настраивает клиента сам.

## Обслуживание агента

| Действие            | Где и когда                                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Обновить агента** | Кнопка на странице ноды и значок «обновление» в списке нод — когда вышла новая версия. Служба перезапускается   |
| **Переустановить**  | «Установить агента» ещё раз. Настройки сохраняются, служба агента перезапускается (см. ниже)                    |
| **Ключ агента**     | Перевыпуск ключа (если он утёк). Старый перестаёт работать сразу — агента нужно переустановить командой из окна |
| **Удалить агента**  | Убирает с сервера всё, что делала админка, и возвращает сервер к виду до установки. Нода остаётся в списке      |
| **Журнал агента**   | Вкладка на странице ноды: последние 300 строк, обновляется при каждом открытии и кнопкой «Обновить»             |

При перезапуске службы агента (обновление, переустановка) клиенты связь не
теряют, если WireGuard работает модулем ядра. Если модуля ядра нет, интерфейсы
держит wireguard-go внутри агента (на странице ноды — «WireGuard: wireguard-go»):
тогда VPN на время перезапуска кратковременно прерывается.

Если сервер перезагрузился, а админка в это время недоступна, VPN всё равно
поднимется: агент помнит последние настройки.

## Порты: что указывать

- **Порт интерфейса** — UDP-порт на его ноде. На одной ноде порты не
  повторяются.
- **Порт на точке** — порт на релее, к которому подключаются клиенты. На
  одном релее порты точек, пробросов и собственных интерфейсов релея не
  повторяются.
- Порт, который на сервере уже занят другой программой, админка выбрать не
  даст (агент сообщает занятые порты).
- Не забудьте открыть порт в файрволе хостера, если он есть.

## Статусы

| Где                  | Статус             | Что значит и что делать                                                            |
| -------------------- | ------------------ | ---------------------------------------------------------------------------------- |
| Нода                 | Ожидает агента     | Нода создана, агент ещё не установлен                                              |
| Нода                 | Установка…         | Идёт установка по SSH — смотрите журнал задачи                                     |
| Нода                 | Online / Offline   | Агент на связи / нет. Offline — через ~20 с после обрыва связи; проверьте сервер   |
| Нода                 | Ошибка             | Установка не удалась — причина в журнале задачи                                    |
| Нода, «Конфигурация» | Ожидает агента     | Настройки применятся, когда на ноде будет установлен агент                         |
| Нода, «Конфигурация» | Применяется…       | Агент получает и применяет настройки                                               |
| Нода, «Конфигурация» | Актуальна          | Настройки на сервере совпадают с админкой                                          |
| Нода, «Конфигурация» | Не применена       | Нода недоступна — настройки применятся, когда агент выйдет на связь                |
| Нода, «Конфигурация» | Ошибка применения  | Агент не смог применить настройки — текст в подсказке и на странице ноды           |
| Интерфейс            | Up / Down          | Работает / выключен                                                                |
| Интерфейс            | Ошибка             | Агент не смог поднять интерфейс — текст ошибки на странице ноды и в журнале агента |
| Копия интерфейса     | Ожидает агента     | На ноде копии ещё нет агента — копия поднимется после установки                    |
| Интерфейс (таблица)  | +N копий, трафик → | Сколько у интерфейса копий (подробности — в подсказке) и куда релей перевёл трафик |
| Пир                  | Онлайн             | Handshake свежее 3 минут                                                           |

## Если что-то не работает

- **Клиент не подключается.** Посмотрите handshake пира. Если его нет —
  проверьте адрес в конфиге (колонка «Подключение клиентов» у интерфейса),
  открыт ли порт у хостера, для релея — статус туннеля на странице ноды.
- **«Ошибка применения» у ноды** (колонка «Конфигурация», на странице ноды —
  «Ошибка применения конфигурации»). Прочитайте текст: чаще всего порт занят
  другой программой. Освободите порт — агент применит настройки сам.
- **Трафик идёт не туда, копия не подхватывает трафик.** Проверьте режим точки:
  переключение на копии работает только через релей панели. Предупреждения в
  окне точки подскажут, что не так.
- **Нода Offline.** На сервере: `systemctl status wg-admin-agent` и
  `journalctl -u wg-admin-agent -n 100`. Если агент работает, но не видит
  админку — проверьте адрес бэкенда и доступность с сервера.
- **На карточке «Хост» связь «HTTP — запасной путь».** Агент работает, но
  прокси перед админкой не пропускает WebSocket: настройки и статистика
  доходят с задержкой в несколько секунд. Включите проксирование WebSocket
  для пути `/api/v1/wg-agent/link` — агент сам вернётся на постоянный канал
  в течение 10 минут.
- **Установка агента падает.** Журнал задачи показывает каждый шаг со временем —
  по последней строке видно, на чём остановилось.
